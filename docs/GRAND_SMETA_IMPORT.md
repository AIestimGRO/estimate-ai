# ГРАНД-Смета (GSFX) → исходная ОС

## Пользовательский сценарий

На главной странице есть отдельная форма загрузки **одного файла GSFX**. Заполненный Excel-отчёт РИМ для обычного сценария не требуется. После загрузки создаётся
черновик в рабочем каталоге сессии, извлекаются позиции и вложенные ресурсы,
показывается редактируемая таблица. Пользователь может менять номер, шифр,
название, единицу, количество, раздел, цену, добавлять и исключать строки.
Можно экспортировать Excel (совместимый со стандартным импортом ОС) либо
продолжить в существующий предварительный просмотр/подбор аналогов.

**Граница текущей реализации (23.11.2026):** автоматический расчёт
подтверждён для проверенных категорий РИМ ФСНБ-2022, дополнение 19,
с однозначными коэффициентами и территориальными нормативами. На эталонной
ЛСР без материалов (Республика Саха (Якутия), зона 4) рассчитаны 11 из 11
нормативных позиций с отклонением от отчёта ГРАНД-Сметы не более 3 копеек
по каждой позиции; ещё две позиции имеют явные цены в GSFX. Это **не**
универсальный расчёт для всех редакций и регионов ГРАНД-Сметы. Например,
для ФСНБ-2022, дополнение 17, с активными общесметными коэффициентами
автоматическая цена пока остаётся пустой. Не объявлять такие строки
рассчитанными, пока не добавлена и не сверена соответствующая методика.

## Правила безопасности и нормализации

- Из GSFX читаются все позиции, включая код 43-1 и погрузочные работы.
- Для нормализации используются только catalog_items, у которых
  catalog_sources.name='main'. База ТКП не используется. Запрос к SQLite
  выполняется read-only. Цены из каталога не подменяют исходную цену сметы.
- При однозначном совпадении шифра, типа работы и единицы переводим масштаб
  с одновременным пересчётом количества, цены и удельных трудозатрат,
  сохраняя общую стоимость и суммарные трудозатраты.
  Смешанные масштабы в каталоге, непроверенное название и неизвестная единица
  отмечаются для ручной проверки, а не подменяются по догадке.
- Исходные значения GSFX сохраняются на отдельном листе «Сверка с GSFX».
- Явные единичные цены погрузки/перевозки читаются непосредственно из
  `PriceCurr` позиции, если нет ресурсов и единственный вид стоимости
  однозначен. Цена отдельной машины не становится ценой работы.
- При поддерживаемом нормативе из GSFX собираются расценки материалов,
  оплаты труда рабочих и машинистов, эксплуатации машин, транспорта,
  коэффициенты позиции, накладные расходы и сметная прибыль. Расчёт ведётся
  отдельно от цен базы аналогов. Публикуемая справочная таблица НР/СП
  сохранена в `core/data/nr_sp_fsnb2022_dop19.json`, генератор —
  `scripts/import_nr_sp_reference.py`. Источник: рекомендуемая привязка
  НР/СП ФСНБ-2022, дополнение 19, 24.08.2026, приказы 812/пр и 774/пр.
- Для неподдерживаемых смет, неполных расценок и нераспознанных коэффициентов
  цена остаётся пустой: подбор по ней блокируется до проверки/исправления.
  Отсутствующий материал в специально подготовленной ЛСР без материалов
  не оценивается из базы; исключение отражается в происхождении цены.
- Необязательный заполненный отчёт РИМ всё ещё принимается старым
  программным API для контрольной сверки, но интерфейс его не запрашивает.
- Нормализованные названия не должны терять цифровые технические параметры.
- Файлы хранятся отдельно для каждого токена; предпросмотр и экспорт
  проверяют владельца сессии так же, как обычный импорт.
- Для импорта ограничен размер файла и объём Data.xml; при слишком большом
  количестве позиций сервер отказывает, не генерируя огромную HTML-таблицу.
- SQLite, TKP и механизм подбора аналогов не изменяются; миграция БД не нужна.


## Форма ОС и безопасное обновление

- Шапка (номер задачи, объект, регион, коэффициент) располагается над таблицей. Заголовки в типовой форме РИМ: строка 27, нумерация: 28, тело: с 29.
- N: «Перечень ГЭСН/ФЕР/ТЕР» (исходный шифр), O: отдельный «/КР», P: «Код раздела». После подбора O получает суффикс /КР при найденных аналогах; иначе остаётся исходный шифр.
- Перед выдачей WA проверяется структура OOXML; обычные файлы не пересобираются повторно. Требуется отдельно проверить реальный проблемный файл в Microsoft Excel, прежде чем считать проблему «Восстановление содержимого» полностью устранённой.
- Изменения только через work-ветку GitHub, pytest, CI, merge в feature/admin-ui; на сервере — проверяемые PowerShell-команды с бэкапом и откатом. Не заменять исходники вручную ZIP-архивом.

## Проверки и ограничения

Регрессионные тесты: расчёт НР/СП и коэффициентов для РИМ из GSFX,
отказ от расчёта при неполных данных, импорт одного GSFX, позиции 163/164, Excel→стандартный импорт,
нормализация 100 м→м, сохранение общей стоимости, смешанные масштабы,
исключение ТКП, неназначение цен, предпросмотр и подтверждение неоднозначностей.
Работу с реальной заполненной базой и цены из выгрузок необходимо проверить
отдельно на staging до обновления рабочего сервера.

Текущие черновики хранятся в оперативной памяти процесса. После перезапуска
неотправленные правки пропадают; скачанный Excel остаётся у пользователя.
