# ГРАНД-Смета (GSFX) → исходная ОС

## Пользовательский сценарий

На главной странице есть отдельная форма загрузки GSFX. По загрузке создаётся
черновик в рабочем каталоге сессии, извлекаются позиции и вложенные ресурсы,
показывается редактируемая таблица. Пользователь может менять номер, шифр,
название, единицу, количество, раздел, цену, добавлять и исключать строки.
Можно экспортировать Excel (совместимый со стандартным импортом ОС) либо
продолжить в существующий предварительный просмотр/подбор аналогов.

## Правила безопасности и нормализации

- Из GSFX читаются все позиции, включая код 43-1 и погрузочные работы.
- Для нормализации используются только catalog_items, у которых
  catalog_sources.name='main'. База ТКП не используется. Запрос к SQLite
  выполняется read-only. Цены из каталога не подменяют исходную цену сметы.
- При однозначном совпадении шифра, типа работы и единицы переводим масштаб
  с одновременным пересчётом количества и цены, сохраняя стоимость.
  Смешанные масштабы в каталоге, непроверенное название и неизвестная единица
  отмечаются для ручной проверки, а не подменяются по догадке.
- Исходные значения GSFX сохраняются в дополнительных столбцах Excel.
- Неподтверждённую цену работы из GSFX нельзя вычислять простой суммой
  ресурсных цен: цена остаётся пустой; подбор блокируется до её ввода.
- Нормализованные названия не должны терять цифровые технические параметры.
- Файлы хранятся отдельно для каждого токена; предпросмотр и экспорт
  проверяют владельца сессии так же, как обычный импорт.
- Для импорта ограничен размер файла и объём Data.xml; при слишком большом
  количестве позиций сервер отказывает, не генерируя огромную HTML-таблицу.
- SQLite, TKP и механизм подбора аналогов не изменяются; миграция БД не нужна.

## Проверки и ограничения

Регрессионные тесты: позиции 163/164, Excel→стандартный импорт,
нормализация 100 м→м, сохранение общей стоимости, смешанные масштабы,
исключение ТКП, неназначение цен, предпросмотр и подтверждение неоднозначностей.
Работу с реальной заполненной базой и цены из выгрузок необходимо проверить
отдельно на staging до обновления рабочего сервера.

Текущие черновики хранятся в оперативной памяти процесса. После перезапуска
неотправленные правки пропадают; скачанный Excel остаётся у пользователя.
